# Defensa técnica

Respuestas de apoyo basadas en el código real. El estudiante debe revisarlas, expresarlas con sus palabras y poder explicar el código sin asistencia.

1. **¿Por qué paginar en el servidor?** Para no descargar miles de productos y ventas al abrir un listado. El controlador limita tamaño a 100 y pasa `PageRequest` al repositorio. Oracle ejecuta la selección ordenada con OFFSET/FETCH y la cuenta para el total cuando Spring Data la necesita; `Page` puede evitar la cuenta si ya infiere el total de una página parcial. El desempate por ID evita orden ambiguo. Código: `controller/ProductoController.java`, `controller/VentaController.java`, `repository/VentaRepository.java`; SQL real en `evidencias-s14/02-sql-paginacion.txt`.

2. **¿Cómo evito una venta a medias?** `VentaServiceImpl.registrar` tiene `@Transactional`: cabecera, detalles y stock se confirman juntos o hacen rollback. Publica el evento dentro de la transacción, pero `AuditoriaListener` lo persiste después de confirmar. Si falla la segunda línea, el stock de la primera vuelve a su valor y no aparece VENTA_REGISTRADA. Código: `service/impl/VentaServiceImpl.java`, `auditoria/AuditoriaListener.java`; regresión: `e2e/flujo-venta.spec.ts` del frontend.

3. **¿Qué pasa si vence el token durante una venta?** `AuthService` calcula el vencimiento y elimina la sesión cuando se agota. El interceptor también captura un 401 de la API y cierra la sesión con aviso y returnUrl interno. Se vuelve al login; después se recupera la ruta, no el contenido de un formulario perdido. El backend rechaza el JWT vencido. Código frontend: `core/auth/auth-service.ts`, `core/interceptors/error-interceptor.ts`; backend: `security/JwtAuthenticationFilter.java`. Casos: autenticación y E2E-14.

4. **¿Por qué invalidar Redis después de vender?** El stock cambió. Una página cacheada podría seguir ofreciendo el stock anterior. `@CacheEvict(cacheNames="productos", allEntries=true)` invalida todas las combinaciones de páginas y órdenes. La siguiente lectura vuelve a consultar Oracle. Si Redis falla se advierte y se usa la base; esto es resiliencia básica, no una garantía de consistencia distribuida ante todas las caídas. Código: `VentaServiceImpl.java`, `config/CacheConfig.java`; flujo integrado calienta caché y comprueba stock sin F5.

5. **¿Log, columna o bitácora?** El log explica una solicitud y su duración; creado_por indica quién creó una fila, modificado_por quién la cambió por última vez; la bitácora guarda eventos del negocio en el tiempo. requestId permite cruzarlos. Código: `config/RequestIdFilter.java`, `config/AuditoriaConfig.java`, `entity/Venta.java`, `entity/AuditoriaEvento.java`.

6. **¿Cuándo considero estable una prueba?** Repite el mismo comportamiento tres veces desde datos propios, sin retries ni esperas fijas. Espera respuestas y elementos visibles. Una prueba anterior suponía que su producto estaría en la primera página y fallaba con más datos: ahora recorre el paginador real. E2E-12 además detectó el nombre accesible incorrecto del selector; la traza mostró el control esperado y se añadió aria-label. Código frontend: `e2e/flujo-venta.spec.ts`, `e2e/autonoma.spec.ts`, `playwright.config.ts`. Incidencias INC-06 e INC-08.

7. **¿Por qué no basta con esconder Auditoría?** Cualquiera puede escribir la URL o llamar la API. El menú mejora la experiencia; el guard bloquea la página y Spring Security comprueba el permiso en el servidor. Código: `config/SecurityConfig.java`; frontend: `app.routes.ts`, `layout/sidebar/sidebar.ts` y E2E-13. Postman verifica 403 con vendedor.

8. **¿Cómo se comparten filtros?** La URL contiene usuario, acción, fechas, página y tamaño. `withComponentInputBinding` alimenta los inputs; `rxResource` consulta de nuevo. Cambiar filtros vuelve a página 0 y F5 conserva el estado. Código frontend: `features/auditoria/auditoria.ts`, `features/ventas/pages/venta-list/venta-list.ts`, `shared/components/paginador/paginador.ts`.

9. **¿Por qué Flyway y validate?** Flyway versiona los cambios del esquema; validate comprueba que las entidades coincidan sin crear columnas silenciosamente. El esquema legado se incorporó con baseline 2 antes de aplicar V4. No haría repair sobre una base de producción sin investigar el fallo. Código: `db/migration/V4__auditoria.sql` y `application-dev.yaml`; evidencia real en `evidencias-s14/05-migracion.json`.

10. **¿Qué límites tiene esta versión?** Los E2E cubren rutas y errores, no prueban carga concurrente intensiva ni todos los fallos de infraestructura. El registro de auditoría posterior al commit no usa outbox durable. La anulación cambia estado sin devolución automática. El filtro por categoría del listado actúa sobre la página actual y lo indica la pantalla; el buscador de la venta sí consulta el servidor. Identifico estos límites para no prometer comportamientos que no medí. Código: `AuditoriaListener.java`, `VentaServiceImpl.anular`; frontend `producto-list.html`, `venta-form.ts`.

Los paths de backend anteriores parten de `src/main/java/pe/edu/pe/PharmaBackend/`, salvo migraciones y YAML que parten de `src/main/resources/`. Los de frontend parten de `src/app/`, excepto `e2e/` y la configuración de Playwright.
